## Scaling changes the problem

An Ising machine encodes a problem as binary spins joined by weighted couplings; a low-energy spin configuration represents a good solution. To update one spin, the machine reads its neighbors and couplings, accumulates a local field, and samples a new state. One sweep attempts to update every spin once.

Scale, not the individual update, creates the system challenge. Practical problems outgrow one accelerator's on-chip storage, so the system must partition the coupling graph across devices. This partitioning creates two boundaries: a memory boundary within each device and a communication boundary between devices.

[[FIG:workflow]]

The same platform can be memory-bound at one size, synchronization-bound at another, and communication-bound after partitioning. Sparse regular graphs expose parallelism through graph coloring: spins within one color share no edges and can update together. Each color step must still observe committed neighbor values, so GPUs execute global barriers and distributed systems exchange boundary states.

> Asking which device is fastest obscures the architectural question. Instead, ask **which term limits this workload at this size and mapping?**
